# راه‌اندازی آزمایشی در محل جدا

این راهنما مسیر دودآزمایی محلی است؛ نصب کامل جمع‌آوری و بازسازی رتبه‌بندی را تضمین نمی‌کند. حساب‌ها و پایگاه فعال را در مقصد آزمایشی معرفی نکنید.

نسخه‌های آزمایش‌شده: Windows، Go 1.24.4، Node 22.17.0، npm 10.9.2 و Python 3.13.5. برای ابزارهای جمع‌آوری کدال، وابستگی‌های `go-app/py2/pyproject.toml` و `go-app/py/requirements.txt` جدا هستند؛ فایل ریشهٔ `requirements-paper-offline-test.txt` فقط محیط آزمون کاغذی آفلاین است.

در کپی مستقل کد، در PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-paper-offline-test.txt
.\.venv\Scripts\python.exe -m pytest ranking_research/tests/test_experimental_paper.py::test_real_cli_buy_sell_accounting_preview_and_next_day_replay -q
Set-Location go-app
go test ./...
go build ./...
Set-Location ..\client
npm ci --legacy-peer-deps
npm run build
npm run test:csv
npm run test:errors
npm run test:indicators
```

نصب npm بدون گزینهٔ سازگاری فعلاً بر سر peer نسخه‌های React 19 و react-table 7 شکست می‌خورد. این گزینه اصلاح تعارض پشتیبانی کتابخانه نیست و باید در ارتقای بعدی برطرف شود.

برای اجرای backend، `go-app/.env.example` نمونهٔ نام متغیرهاست. `go-app/.env` مستقل با SMTP و JWT آزمایشی و پورت آزاد بسازید و مقادیر محرمانهٔ واقعی را در مخزن قرار ندهید؛ نبود SMTP یا JWT باعث توقف فرآیند می‌شود. به‌منظور آزمایش، `CODAL_AUTO_SYNC_ENABLED=0` و `QVT_PAPER_OBSERVER_ENABLED=0` بمانند. بدون PostgreSQL، endpoint سلامت باید نبود داده را نشان دهد؛ در صورت نیاز به داده، فقط URL پایگاه بازیابی‌شدهٔ آزمایشی و نام `CDF_CANONICAL_DB` همان پایگاه را بدهید. هرگز پایگاه فعال را به مقصد تست معرفی نکنید. فرایندهای فرزند `paper_cycle.py` به‌طور پیش‌فرض با همان Python اجراکننده ساخته می‌شوند؛ `CDF_PAPER_PYTHON` امکان تعیین مسیر Python دیگری را می‌دهد.

مصنوعات موردنیاز مسیر تولیدی، شامل قرارداد قفل‌شده، universe، بایگانی مالی، دادهٔ بازار و ranking، هنوز یک بستهٔ قابل حمل و کامل با manifest مستقل ندارند. چند مسیر ورودی قدیمی مطلق یا وابسته به ساختار دستگاه‌اند. بنابراین نتیجهٔ آزمون fixture بالا معادل راه‌اندازی روزانهٔ کامل نیست. dump و پشتیبان حساب حاوی اطلاعات خصوصی‌اند و باید جدا از Git نگهداری شوند.

در دو builder اصلی، `V1237_OWNER_PACK` مسیر پوشهٔ دارای `registration.json`، `V1237_OWNER_INPUTS` پوشهٔ بایگانی مالی و `V1237_SHARE_PATH` مسیر snapshot سهام را بازتعریف می‌کنند. نبود متغیر همان پیش‌فرض قبلی را حفظ می‌کند. این سه گزینه به‌تنهایی تمام مسیرهای تاریخی داخل manifestها را قابل انتقال نمی‌کنند.

فرمان بررسی یکجا `./scripts/check.ps1` است؛ `-Only Go`، `-Only Python` یا `-Only Frontend` زیرمجموعه را انتخاب می‌کند. این فرمان فقط متغیرهای ضروری سیستم را به فرآیند آزمون می‌دهد و نتیجهٔ هر بخش را مستقل گزارش می‌کند. آزمون زندهٔ refresh جداست و خودکار فعال نمی‌شود؛ skip آن در خروجی صریح است.

برای خواندن شواهد قدیمی در کپی جابه‌جاشده، `CDF_EVIDENCE_OLD_ROOT` ریشهٔ ثبت‌شدهٔ سابق و `CDF_EVIDENCE_NEW_ROOT` ریشهٔ بازیابی‌شده را مشخص می‌کنند. هر دو باید هم‌زمان تنظیم شوند؛ مسیر خارج از ریشه یا دارای پیمایش رد می‌شود و محتوای manifest و کنترل hash عوض نمی‌شود. این نگاشت به‌تنهایی ثابت نمی‌کند همهٔ ورودی‌های دیگر بازار و رتبه‌بندی در بسته هستند.

برای گزارش وضعیت کاغذی در محیط جدا، `CDF_STATUS_REFERENCE_RANKING` فایل رتبه‌بندی مرجع و `CDF_STATUS_LOCAL_CALENDAR` فایل تقویم محلی را تعیین می‌کنند. در نبود آنها مسیرهای قبلی حفظ می‌شوند؛ فایل انتخابی باید وجود داشته باشد و مسیر و hash آن در گزارش ثبت می‌شود. از فایل‌های ساختگی یا کپی‌های مستقل در آزمون استفاده کنید.

کتابخانهٔ پژوهش مسیر پروژه را از محل کد می‌گیرد. اگر سه cache مرجع وجود نداشته باشند، اتصال پایگاه فقط با `CDF_RESEARCH_DSN` صریح انجام می‌شود و نبود آن خطای مشخص می‌دهد؛ این مقدار محرمانه است و نباید در Git یا گزارش درج شود. وجود cache معتبر امکان اجرای آفلاین را فراهم می‌کند.
