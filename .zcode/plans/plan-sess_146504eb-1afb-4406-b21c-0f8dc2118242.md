# ساخت نمایشگر صورت‌های مالی کامل (سود و زیان / ترازنامه / جریان نقد)

## Context

در مقایسه با پلتفرم‌های مشابه، بزرگ‌ترین شکاف این بود: **دیتای صورت‌های مالی در SQL Server (`codal.dbo.miandore2`) جمع می‌شود ولی هیچ UI نمایشی ندارد** — کاربر فقط نمودار رشد EPS می‌بیند. دیتای موجود و پرشده در `miandore2`:
- **سود و زیان** (تجمعی ۳/۶/۹/۱۲ ماهه، از ~۱۳۹۷): EPS و EPS عملیاتی و سرمایه (ستون‌های Num1/Num4/Num2)، درآمد (RevenueNew/LY/FYPrev)، سود عملیاتی (OperatingProfitNew/LY/FYPrev)، هزینه مالی (FinanceCostsNew/LY)، سایر غیرعملیاتی، سود خالص مبلغی (NetProfitAmount/LY/FYPrev)
- **ترازنامه** (نقطه‌ای، دوره جاری + سال قبل): TotalAssets، CurrentAssets، TotalLiabilities، CurrentLiabilities، TotalEquity (+LY)
- **جریان نقد عملیاتی** (تجمعی): OperatingCashFlow/LY/FYPrev

تصمیم‌های تأییدشده: بخش جدید در **داشبورد** بعد از ScoreBreakdown (با ۳ تب داخلی)، و نمایش **دیتای موجود** + متریک‌های محاسباتی (بدون پارسر جدید کدال). منبع: **SQL Server (miandore2)** چون پوشش کامل ۲۷۱ شرکت را دارد؛ مسیر canonical PG (فقط ۳۸٪ ترازنامه دارد) خارج از محدوده این کار.

## Backend — `go-app/handlers/financial_statements.go` (فایل جدید)

- `GET /api/financial-statements?companyName=<نماد>&limit=12` داخل بلاک protected در `main.go` (کنار `/summary`)، ثبت: `protected.GET("/financial-statements", handlers.GetFinancialStatements)`
- الگوی کپی‌شده از `handlers/sales_data.go` (کوئری با `CompanyName = @companyName` روی `config.GetDB()`) + مرتب‌سازی مثل `getProfitPoints` در `handlers/ai_stock_handler.go:855` با `dbo.fn_JalaliKey(ReportDate) DESC`، `TOP (@limit)` (سقف ۴۰، پیش‌فرض ۱۲ گزارش ≈ ۳ سال)
- همه ستون‌ها `sql.NullFloat64` → `*float64` در JSON (تفکیک «نداریم» از صفر) — اسکن مطابق `getProfitPoints`
- **استنتاج دوره**: ماه تاریخ جلالی ReportDate → `durationMonths = month==12 ? 12 : month` + برچسب «۳ ماهه منتهی به …»؛ `fiscalYear` = سال ReportDate
- **متریک‌های مشتق** (سرور، از ستون‌های LY همان ردیف): حاشیه سود عملیاتی/خالص، رشد YoY درآمد و سود خالص، دارایی/بدهی غیرجاری (TA−CA، TL−CL)، نسبت جاری (CA/CL)، بدهی به دارایی (TL/TA)، تبدیل نقد (OCF/سود خالص)
- Response: `{ companyName, unit_meta: {monetary: "million_rial", eps: "rial"}, periods: [...] }` — هر period شامل `report_date, duration_months, fiscal_year, income_statement{}, balance_sheet{}, cash_flow{}, derived{}`، جدیدترین اول

## Client

1. **`client/src/utils/api.ts`** — تایپ‌ها + `fetchFinancialStatements(companyName, limit?)` با همان الگوی `getAuthHeaders()` موجود
2. **`client/src/components/FinancialStatements.tsx`** (کامپوننت جدید، self-fetching با `SkeletonTable` هنگام لود):
   - Props: `{ companyName: string }`؛ useEffect روی تغییر نماد، state لودینگ/خطا/«صورتی ثبت نشده»
   - تب‌های داخلی: **«سود و زیان»** — جدول سطر=خطوط صورت (درآمد، سود عملیاتی، هزینه مالی، سایر غیرعملیاتی، سود خالص، EPS، سرمایه + حاشیه‌ها و رشد YoY)، ستون=دوره‌ها؛ **«ترازنامه»** — جمع دارایی‌ها، جاری/غیرجاری، بدهی‌ها، حقوق صاحبان سهام + نسبت جاری و بدهی/دارایی؛ **«جریان نقد»** — OCF تجمعی + نسبت تبدیل نقد
   - در هر تب یک نمودار recharts کوچک روند (درآمد/سود خالص؛ ترکیب دارایی‌ها؛ OCF) — بازاستفاده از سبک `ChartComponent`/`ScoreBreakdown`
   - فرمت: ارقام فارسی با `faDigits()` از `utils/chartHelpers.ts`، مقیاس تطبیقی (میلیون/میلیارد ریال)، منفی قرمز، YoY سبز/قرمز، تهی = «—»
   - استایل: کارت `rounded-2xl border backdrop-blur-sm shadow-md` + جدول `border-separate border-spacing-y-1` (idiom موجود در `BigDataTable.tsx`/`QvtAnalysisPage.tsx`) + کلاس‌های جفتِ dark
3. **`client/src/App.tsx`** — import لَزی؛ رندر بعد از ScoreBreakdown:
   ```tsx

     <div className="animate-fade-in-up" style={{ animationDelay: "400ms" }}>

     </div>

   ```

## خارج از محدوده (آگاهانه)

- خطوط جزئی‌تر (بهای تمام‌شده، موجودی، CF سرمایه‌گذاری/تأمین مالی) — نیازمند پارسر جدید کدال؛ کار جداگانه
- مسیر canonical PG و مود-gating — این endpoint فقط legacy می‌خواند (فقط‌خواندنی، بدون تغییر دیتا)
