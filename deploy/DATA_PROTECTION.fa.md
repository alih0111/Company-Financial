# حفاظت از داده و محدودکردن برداشت انبوه

تاریخ: ۲۰۲۶-۱۱-۰۷. این تغییرها برای کنترل دادهٔ قابل دریافت از وب‌سایت‌اند. هر داده‌ای که مجاز به نمایش باشد می‌تواند ذخیره، عکس‌برداری یا به‌مرور گردآوری شود؛ هیچ محدودکننده‌ای جلوی تمام این کارها را نمی‌گیرد.

## یافتهٔ مهم خارج از وب‌سایت

در بررسی بدون ورود به GitHub، مخزن [alih0111/Company-Financial](https://github.com/alih0111/Company-Financial) عمومی بود. فهرست شاخهٔ اصلی ۵۵۴ فایل با پسوند داده/JSON و ۲۱۶ فایل زیر مسیرهای پژوهش و استراتژی داشت. این آمار شامل فایل‌های تنظیمات JSON هم هست و به معنی ۵۵۴ دیتاست مستقل نیست. برای این بررسی محتوای فایل‌های حاوی راز چاپ یا بازنشر نشد.

**خصوصی‌کردن این مخزن و هر مخزن/registry دارای تصویر کامل برنامه، پیش‌نیاز حفاظت از داده است.** کنترل API روی دسترسی مستقیم GitHub، cloneها، نسخه‌های قبلاً دانلودشده و mirrorها اثر ندارد. حذف فایل از آخرین commit نیز آن را از تاریخچه پاک نمی‌کند. مخزن در این کار خصوصی نشده است؛ دسترسی مدیریتی GitHub هنوز متصل نیست. مسیر تنظیمات مخزن در GitHub بخش Settings → General → Danger Zone → Change repository visibility است. خصوصی‌شدن هم نسخه‌های قبلیِ دیگران را پس نمی‌گیرد.

اگر کد عمومی لازم است، یک مخزن جدا با نمونه‌داده و بدون تاریخچهٔ دادهٔ واقعی آماده کنید؛ همین مخزنِ حاوی پژوهش و snapshotها را عمومی نگه ندارید. رمزهای قدیمیِ نوشته‌شده در منبع باید مطابق [گزارش امنیت](SECURITY.fa.md) در سرویس مبدأ تعویض شوند. اطلاعات دسترسی را در پیام نفرستید.

CI همچنان آزمون‌ها را اجرا می‌کند، اما مرحلهٔ آماده‌کردن تصویر انتشار از مخزن عمومی عمداً متوقف می‌شود. این کنترل جلوی push به GitHub را نمی‌گیرد؛ **پیش از push تغییرها، وضعیت مخزن را اصلاح کنید.** هیچ push یا تغییر visibility در این کار انجام نشده است.

خلاصهٔ عمومی از `/api/strategy/summary` و صفحهٔ `/performance` ارائه می‌شود. فقط فیلدهای مشخصِ نتیجهٔ تجمیعی و جدول سالانه کپی می‌شوند؛ فایل ورودی، معاملات، دارایی‌ها، مسیر روزانهٔ سرمایه، پارامترهای کامل و لینک دانلود در آن نیست. در دادهٔ فعلی فقط آزمایش ماهانهٔ شروع ۱۴۰۱ موجود است؛ نتیجهٔ نسخهٔ فصلی ۱۴۰۲ به جای نتیجهٔ ماهانه نمایش داده نمی‌شود.

آرشیو کاملِ صفحه‌های قدیمی برای حساب عادی با همین نمای خلاصه جایگزین شده است. نام و شناسهٔ شرکت‌ها، بدون قیمت و امتیاز، برای انتخاب نماد قابل دریافت است. این فهرست اطلاعات هویتیِ عمومی بازار است؛ سهمیهٔ نماد/ردیف اختصاصی را مصرف نمی‌کند، ولی درخواست و بایت آن حساب می‌شود.

## سهمیه و نحوهٔ محاسبه

پیش‌فرض هر حساب عادی در هر روز تهران:

| محدودیت | مقدار |
| --- | --- |
| درخواست داده | ۳۰۰ |
| عناصر آرایهٔ داده در پاسخ‌ها، شامل آرایه‌های تو در تو | ۱۲٬۰۰۰ |
| بایت JSON تحویل‌شده | ۸ MiB |
| شناسهٔ متفاوت نماد در درخواست یا پاسخ | ۴۰ |
| اندازهٔ صفحهٔ بازار/رتبه‌بندی | حداکثر ۲۰ |
| تاریخچهٔ قیمت در هر درخواست | حداکثر ۷۳۰ رکورد اخیر |
| اندازهٔ پاسخ عادی | حداکثر ۲ MiB |
| درخواست هم‌زمان داده برای هر حساب | ۲ |
| درخواست هم‌زمان حساب‌های عادی در کل برنامه | ۳۲ |
| نرخ درخواست داده برای حساب عادی | ۳۰ در دقیقه |

هزینهٔ درخواست قبل از خواندن داده ثبت می‌شود. پاسخ JSON تا تأیید هزینهٔ کاملش در سرور می‌ماند؛ اگر سهمیهٔ ردیف، نماد یا بایت کافی نباشد، بدنهٔ اصلی به کاربر فرستاده نمی‌شود. درخواست ناموفق ممکن است سهمیهٔ درخواست مصرف کند، ولی پاسخ ردشده سهمیهٔ ردیف و بایت را مصرف نمی‌کند. شمارش شناسه‌ها محافظه‌کارانه است؛ نام‌های مستعار متفاوت ممکن است جدا حساب شوند.

مصرف در PostgreSQL با تراکنش و قفل سطر ثبت می‌شود؛ درخواست موازی، ورود مجدد، نشست دیگر، restart و تغییر IP سهمیهٔ حساب را بازنشانی نمی‌کنند. زمان بازنشانی نیمه‌شب تهران است. سقف IP مشترک ده برابر پیش‌فرض حساب است تا ساخت چند حساب روی یک شبکه محدود شود؛ IPv6 بر اساس /64 گروه‌بندی می‌شود. IP خام و محتوای پاسخ در این جدول‌ها ذخیره نمی‌شوند؛ کلیدها HMAC هستند. این سقف شبکه ممکن است کاربران یک NAT سازمانی را هم محدود کند.

سقف هم‌زمانی و نرخ دقیقه‌ای در حافظهٔ هر فرایند است؛ سهمیهٔ روزانه بین فرایندها مشترک می‌ماند. محدودکنندهٔ ارسال ایمیل و کد ثبت‌نام همچنان تک‌replica است. برای گسترش به چند replica، مخزن مشترک کد و محدودکننده‌های لحظه‌ای و تنظیم لایهٔ ورودی لازم است.

دریافت قیمت‌گذاری سبد شخصی هم سهمیه دارد تا ساخت سبد بزرگ، مسیر جایگزین برداشت قیمت‌ها نشود. مدیریت حساب، مشاهدهٔ سهمیه، خروج و ویرایش/حذف دارایی مستقل از سهمیهٔ دریافت داده باقی می‌مانند. محدودیت API مجوز خواندن یا تغییر اطلاعات کاربران دیگر نمی‌دهد.

## چت و پیشنهاد سبد

پیشنهاد سبد ماهانه در بک‌اند، با حفظ قواعد بافر رتبهٔ ۸ و آستانهٔ انحراف ۵ واحد درصد محاسبه می‌شود. حداکثر ده دارایی ورودی پذیرفته می‌شود؛ فقط دارایی‌های همان پیشنهاد و خروجی لازم بازگردانده می‌شوند. ورودی سبد در این مسیر ذخیره نمی‌شود و معامله‌ای اجرا نمی‌شود. نبود کل رتبه‌بندی در مرورگر، نتیجهٔ مدل را به رتبه‌های همان صفحه محدود نمی‌کند.

حساب عادی در چت فقط به یک مجموعهٔ کوچک از شرکت‌های مرتبط با پرسش و پنج شرکت برتر دسترسی دارد. ابزارها روی همان مجموعه کار می‌کنند و هزینهٔ خروجی پیش از ورود به متن مدل ثبت می‌شود. ابزار تحلیل کل سبد و خواندن آزاد همهٔ دارایی‌ها برای حساب عادی عرضه نمی‌شود. خروجی ابزار حداکثر ۶۴ KiB است. برای SSE، ۵۰ ردیف و ۶۴ KiB از پیش رزرو می‌شود و ارسال واقعی هم سقف دارد؛ خطای سهمیه به مسیر نامحدود دیگری fallback نمی‌کند.

## تنظیم مدیر

منوی مدیر «دسترسی دادهٔ کاربران» در `/admin/data-access` اضافه شده است. می‌توان نام کاربری را جست‌وجو کرد، سقف‌ها را تغییر داد یا دریافت دادهٔ حساب را غیرفعال کرد. بیست حساب با بیشترین رد درخواست/مصرف امروز نشان داده می‌شوند. کاهش سقف یا تغییر مجوز، مصرف قبلی روز را صفر نمی‌کند. مدیر خودش سقف عادی ندارد و آرشیو کامل را می‌بیند؛ حساب مدیر نباید مشترک یا عمومی باشد.

APIهای مدیریت نیز فقط با نقش مدیر، کوکی معتبر و برای PUT با Origin معتبر کار می‌کنند:

- `GET /api/admin/data-access`: مصرف بالای امروز.
- `GET /api/admin/data-access/:username`: وضعیت همان حساب.
- `PUT /api/admin/data-access/:username`: بدنهٔ `{ "enabled": true, "limits": { "requests": 300, "records": 12000, "bytes": 8388608, "symbols": 40 } }`.
- `GET /api/data-access`: فقط وضعیت حساب خود کاربر.

پیش‌فرض‌ها در `deploy/.env` با `CDF_DATA_DAILY_REQUESTS`، `CDF_DATA_DAILY_RECORDS`، `CDF_DATA_DAILY_BYTES` و `CDF_DATA_DAILY_SYMBOLS` تنظیم می‌شوند. مقدار صفر یا خارج از محدوده، محدودکننده را خاموش نمی‌کند؛ شروع برنامه با تنظیم نامعتبر رد می‌شود. سیاست ذخیره‌شدهٔ یک حساب بر پیش‌فرض اولویت دارد.

## ارتقا و انتشار

نصب تازه اکنون ۲۲ فایل SQL و ۵۴ جدول دارد. روی دیتابیس موجود، پس از پشتیبان و migration نشست شمارهٔ ۱۴۰، migration افزایشی ۱۵۰ را با نقش مالک اعمال کنید:

```bash
python3 deploy/backup.py
docker compose --env-file deploy/.env exec -T db psql -U rfa_owner -d company_financial -v ON_ERROR_STOP=1 -f /schema/150_data_access.sql
docker compose --env-file deploy/.env exec -T db psql -U rfa_owner -d company_financial -v ON_ERROR_STOP=1 -c 'GRANT SELECT, INSERT, UPDATE, DELETE ON auth.data_policies, auth.data_usage, auth.data_targets, auth.data_ip_usage TO rfa_app;'
docker compose --env-file deploy/.env up -d --build --wait
```

این ارتقا روی دیتابیس فعال دستگاه اجرا نشده؛ آزمون‌ها روی دیتابیس جدا هستند. بدون جدول‌های جدید readiness پاسخ ۵۰۳ می‌دهد و کنترل داده در خطای دیتابیس بسته می‌ماند. حذف جدول مصرف، بازنشانی دستی آن یا بازگردانی پشتیبان قدیمی می‌تواند مصرف روز را عقب ببرد؛ این کارها جزو ابزار کاربر نیستند و نباید برای رفع خطای معمول انجام شوند.

Vite اکنون فقط `client/public-ui` را به خروجی build می‌برد. اصل خروجی‌های پژوهش همچنان در `client/public` و volume خصوصی سرور برای مدیر و محاسبه باقی است. فرانت و API باید پشت Go/Caddy یک مبدأ باشند؛ پوشهٔ `client/public` یا volume مدل‌ها را با nginx، CDN، object storage یا static hosting جداگانه عمومی نکنید. مسیرهای پژوهش در توسعه هم به Go پروکسی می‌شوند؛ dev server را روی اینترنت باز نگذارید. تصاویر Docker، نسخه‌های پشتیبان و بستهٔ استراتژی باید خصوصی بمانند.

برای نگهداری دوره‌ای، پس از پشتیبان می‌توان هدف‌ها و مصرف شبکهٔ قدیمی‌تر از ۳۰ روز و گزارش مصرف حساب قدیمی‌تر از ۹۰ روز را حذف کرد؛ سطرهای روز جاری را حذف نکنید. این حذف خودکار فعال نشده است تا سیاست نگهداری بدون تصمیم مالک تغییر نکند.

## آزمون و مرز تضمین

آزمون‌های PostgreSQL قفل هم‌زمانی، ماندگاری سهمیه، تغییر IP، چند حساب روی IPv6 مشترک، هزینهٔ ردیف/بایت/نماد، غیرفعال‌کردن حساب و جلوگیری از تحویل بدنهٔ تأییدنشده را پوشش می‌دهند. آزمون‌های دسترسی، GET/HEAD/Range و شکل‌های متفاوت مسیر فایل، نقش مدیر، خروجی خلاصه و محاسبهٔ سبد نیز اضافه شده‌اند. فرانت دریافت صفحهٔ سرور، حذف دانلود همهٔ امتیازها، استفاده از فهرست بدون قیمت برای انتخاب سبد و حفظ ورود هنگام خطای سهمیه را آزمایش می‌کند.

حساب‌های فراوان روی IPهای مستقل، برداشت آهسته در روزهای مختلف، اشتراک حساب و کپی خروجی مجاز کاملاً حذف نمی‌شوند. قبل از ثبت‌نام عمومی گسترده، محافظت ضدربات/WAF ورودی و فرایند رسیدگی به سوءاستفاده باید روی سرویس میزبان تنظیم شوند. سرویس خارجی ضدربات بدون حساب و دامنهٔ واقعی پیکربندی یا تأیید نشده است. شرایط استفاده و مجوز داده می‌توانند ابزار پیگیری باشند و جای کنترل فنی را نمی‌گیرند.

نتیجهٔ نهایی این مرحله: آزمون‌های کامل Go با نقش محدود PostgreSQL موفق، ۶۱ آزمون فرانت موفق، TypeScript/Vite و lint بدون خطا، ساخت اجرایی Linux و Windows موفق و ۱۳ مسیر smoke نسخهٔ production محلی موفق شدند. بررسی کامل npm صفر آسیب‌پذیری گزارش کرد. Docker، مرورگر واقعی، WAF و سرویس مقصد هنوز تأیید نشده‌اند.
