# نتیجهٔ بررسی آماده‌سازی انتشار

تاریخ: ۲۰۲۶-۱۱-۰۷، با مبنای تاریخ تهران.

این گزارش تأیید انتشار عمومی نیست. سرور و دامنه‌ای برای این برنامه در اختیار این کار وجود نداشت و چیزی روی اینترنت منتشر نشد. پایگاه فعال و حساب‌های شخصی دستگاه برای آزمون تغییر نکردند؛ آزمون‌ها روی PostgreSQL جدا با bind محلی و درگاه ۱۵۵۴۲ اجرا شدند.

## بررسی‌های موفق

| بررسی | نتیجه |
| --- | --- |
| آزمون‌های Go، شامل API، نقش‌ها و serving فرانت | موفق؛ `go test ./...` |
| نصب دیتابیس از ابتدا | هر ۲۲ فایل SQL موفق؛ ۵۴ جدول کاربر ایجاد شد |
| حساب اجرای دیتابیس | superuser نیست؛ به auth و بازار دسترسی لازم دارد و به schema خانواده دسترسی ندارد |
| ورود و ثبت‌نام واقعی با PostgreSQL | موفق با نقش `rfa_app`؛ ثبت‌نام نمی‌تواند نقش مدیر بگیرد و کد دوباره مصرف نمی‌شود |
| جداسازی سبد دو کاربر | موفق؛ حذف سبد کاربر دیگر ممکن نیست |
| شش نوشتن هم‌زمان سبد | موفق؛ فقط یک سبد پیش‌فرض ساخته می‌شود |
| تغییر نقش و غیرفعال‌شدن حساب | اثر فوری روی نشست صادرشده؛ ۴۰۳ یا ۴۰۱ مطابق انتظار |
| اعتبار کد ثبت‌نام | انقضای ده‌دقیقه‌ای، سقف پنج تلاش، cooldown و مصرف اتمیک آزمایش شد |
| ارسال ایمیل بدون TLS در production | آزمون سرور SMTP آزمایشی نشان داد قبل از ارسال اطلاعات متوقف می‌شود |
| صورت‌های مالی PostgreSQL | مسیر query، واحدها، نسبت‌ها و حفظ مقدار ناموجود آزموده شد |
| ساخت اجرایی Linux | `linux/amd64` با `CGO_ENABLED=0` موفق |
| ساخت فرانت | TypeScript و Vite موفق، پس از اصلاح وابستگی‌ها |
| تست‌های فرانت | ۶۱ موفق، صفر شکست، شامل شش آزمون امنیت نشست، سهمیه و حافظهٔ مرورگر |
| آزمون‌های پایتون مرتبط | ۱۶ موفق؛ قفل فرایند، FactorMix و ReportFlow |
| خروجی تازهٔ گزارش در production | تست مستقل تأیید می‌کند نسخهٔ تازه از پوشهٔ انتشار خوانده می‌شود، بدون rebuild |
| دودآزمایی HTTP نسخهٔ production محلی | هر ۱۳ مسیر smoke نسخهٔ production محلی موفق؛ بدون `.env` و SMTP؛ سلامت ۲۰۰، سبد بدون ورود ۴۰۱، فایل تنظیمات و API ناموجود ۴۰۴ |
| انتقال دادهٔ بازار | export با snapshot مشترک و restore روی دیتابیس جدا موفق؛ حساب‌ها و نگاشت‌های خصوصی منتقل نشدند |
| بستهٔ استراتژی‌ها | ۱۲۳ فایل از دو manifest با hash تأیید شدند؛ ZIP و CRC بررسی شد |
| بررسی فایل‌های عمومی | ۳۹۶ فایل از نظر الگوهای کلید/رمز و نام‌های حساس داخل ZIP بررسی شدند؛ موردی در این بررسی محدود پیدا نشد |
| تنظیمات انتشار | نحو YAML هر دو فایل، نحو shell نصب و نحو اسکریپت‌های پایتون بررسی شد |
| ساخت کلیدهای انتشار | تولید تصادفی و جلوگیری از بازنویسی فایل موجود بررسی شد؛ مقادیر چاپ نشدند |
| بررسی whitespace تغییرات | `git diff --check` موفق |

## بررسی امنیت تکمیلی

جزئیات کنترل‌ها، یافته‌های وابستگی‌ها، مهاجرت نشست‌ها و موارد عملیاتی در [SECURITY.fa.md](SECURITY.fa.md) آمده است. حذف اطلاعات اتصال از ۱۸ فایل، رمزهای موجود در تاریخچهٔ Git را باطل نمی‌کند؛ تعویض آن‌ها در سرویس مبدأ لازم است. آزمون HTTPS با سرور TLS آزمایشی، کوکی مرورگر و PostgreSQL جدا انجام می‌شود؛ این جای تأیید گواهی دامنهٔ واقعی را نمی‌گیرد.

## حفاظت از برداشت انبوه

راهنمای تغییر رفتار و نتیجهٔ آزمون‌های جدید در [DATA_PROTECTION.fa.md](DATA_PROTECTION.fa.md) است. آزمون ۲۴ رزرو موازی با سقف ۱۰، دقیقاً ۱۰ موفق و ۱۴ رد داشت. تغییر IP و اتصال تازه سقف را برنگرداند؛ بدنهٔ فراتر از سهمیه یا حجم نیز تحویل نشد. GET/HEAD/Range آرشیو برای مهمان و حساب عادی بسته و برای مدیر مجاز است. خروجی build جدید پوشه‌های research و strategies ندارد.

**مخزن GitHub هنوز عمومی است و داده‌های پژوهشی در شاخهٔ منتشرشده دارد؛ این دسترسی با کنترل وب‌سایت برطرف نمی‌شود. پیش از push باید خصوصی شود.**

## محدودیت‌ها و کارهای باقی‌مانده

- Docker Engine روی این میزبان موجود نبود؛ تصویر و Compose واقعاً اینجا اجرا نشدند. CI ساخت و smoke کامل کانتینر تعریف شده، ولی اجرای موفق آن هنوز مشاهده نشده است.
- بررسی بصری مرورگر کامل نشد: مرورگر داخلی به صفحه متصل نشد و خطای attach timeout داد. آزمون HTTP و ساخت فرانت جای بررسی دستی نمایش موبایل و همهٔ صفحه‌ها را نمی‌گیرد.
- تحویل ایمیل با سرویس SMTP واقعی، صدور گواهی دامنه، بازیابی کامل پشتیبان روی سرور مقصد و آزمون بار عمومی هنوز انجام نشده‌اند.
- بررسی کامل `npm audit --audit-level=moderate` پس از ارتقای وابستگی‌ها صفر هشدار گزارش کرد؛ وابستگی‌های توسعه هم در این نتیجه هستند.
- build هنوز هشدار بزرگ بودن chunk نمودار دارد؛ مانع ساخت نیست. بهینه‌سازی بیشتر بارگذاری در آزمون واقعی شبکه قابل بررسی است.
- تست race محلی اجرا نشد، چون ابزار C لازم روی Windows موجود نبود؛ در CI Linux تعریف شده است.
- گردش کامل روزانهٔ داده، بازسازی رتبه‌ها و دفتر کاغذی روی سرور تازه آزموده نشده است. انتقال بستهٔ مدل به‌تنهایی جای بستهٔ کامل بازار و بایگانی ورودی‌های روزانه را نمی‌گیرد. راهنمای انتشار مسیر انتقال و این مرز را توضیح می‌دهد.

بستهٔ آمادهٔ مدل‌ها در `.runtime/strategy-assets.zip` و checksum در `.runtime/strategy-assets.zip.sha256` قرار دارد؛ این فایل‌ها به Git اضافه نشده‌اند. اطلاعات اتصال، فایل‌های `.env` و حساب‌های فعال داخل این بسته نیستند.
