# انتشار RFA روی سرور

این نسخه برای یک سرور Linux با Docker Engine و افزونهٔ Docker Compose آماده شده است. خود مخزن سرور یا دامنه ایجاد نمی‌کند. ثبت‌نام عمومی به SMTP واقعی و تحلیل روزانه به انتقال داده و ورودی‌های معتبر نیاز دارد.

پیش از انتشار یا ارتقا، [راهنمای امنیت و migration نشست‌ها](SECURITY.fa.md) و [حفاظت از داده و migration شمارهٔ ۱۵۰](DATA_PROTECTION.fa.md) را اجرا کنید. مخزنِ حاوی داده باید خصوصی باشد؛ پیش از push، این مورد را بررسی کنید. فایل‌های آمادهٔ انتشار به‌تنهایی به معنی تأیید امنیت سرور مقصد نیستند.

## ۱. تنظیمات مستقل

کد پروژه را روی سرور قرار دهید. Docker و Compose باید نصب باشند. از ریشهٔ پروژه:

```bash
python3 deploy/generate_env.py
chmod 600 deploy/.env
```

این فرمان کلیدهای تصادفی جدید می‌سازد، مقدارشان را چاپ نمی‌کند و فایل موجود را بازنویسی نمی‌کند. رمزها و کلیدهای دستگاه قبلی را همراه کد منتقل نکنید.

در `deploy/.env`:

- برای آزمون اولیه، `SITE_ADDRESS=:80` می‌تواند باقی بماند؛ این حالت HTTPS عمومی ندارد.
- برای انتشار، `SITE_ADDRESS` را نام دامنه، مثلاً `finance.example.com` قرار دهید؛ از پیشوند مسیر و `/` آخر استفاده نکنید.
- رکورد A دامنه باید به IP سرور برسد؛ رکورد AAAA را فقط اگر IPv6 سرور واقعاً تنظیم شده است بسازید. درگاه‌های ۸۰ و ۴۴۳ لازم‌اند.
- `CDF_REGISTRATION_ENABLED=1` فقط پس از تنظیم `SMTP_HOST`، `SMTP_PORT`، `SMTP_EMAIL`، `SMTP_PASSWORD` و آزمودن ارسال واقعی ایمیل باشد. پورت ۵۸۷ از STARTTLS اجباری و ۴۶۵ از TLS مستقیم استفاده می‌کند. `SMTP_FROM` اختیاری است و باید یک آدرس مجاز ارسال باشد.
- مقادیر دارای `$`، `#` یا فاصله را در فایل env با نقل‌قول تکی بنویسید.
- `AI_CHAT_URL`، `AI_API_KEY` و `AI_MODEL` اختیاری‌اند و فقط به بک‌اند می‌رسند. کلید BRS در `BRS_API_KEY` است.
- `CODAL_AUTO_SYNC_ENABLED` ابتدا صفر باشد. پس از انتقال داده، بررسی دسترسی منابع و آزمون دریافت، می‌توان آن را یک کرد.

## ۲. بالا آوردن سرویس‌ها

بخشی از snapshotهای قفل‌شدهٔ FactorMix به علت حجم در Git نیستند. روی دستگاه فعلی که اصل فایل‌ها موجود است:

```powershell
.venv/Scripts/python.exe deploy/package_strategy_assets.py
```

این ابزار فقط فایل‌های موجود در manifest دو استراتژی را پس از بررسی hash بسته‌بندی می‌کند؛ حساب‌های فعال و `.env` را نمی‌خواند. فایل `.runtime/strategy-assets.zip` و checksum آن را کنار کد به سرور منتقل و پیش از build از ریشهٔ پروژه استخراج کنید:

```bash
sha256sum -c strategy-assets.zip.sha256
python3 -m zipfile -e strategy-assets.zip .
```

سپس:

```bash
docker compose --env-file deploy/.env config --quiet
docker compose --env-file deploy/.env up -d --build --wait --wait-timeout 240
docker compose --env-file deploy/.env ps
python3 deploy/smoke.py https://finance.example.com
```

برای آزمون با IP و حالت `:80`، آدرس آزمون آخر `http://SERVER_IP` است. این حالت صرفاً برای بررسی نصب است؛ قبل از پذیرش ورود و ثبت‌نام عمومی، دامنه و HTTPS را تکمیل کنید.

فرانت از Go ارائه می‌شود؛ نیازی به Vite dev server در سرور نیست. فقط Caddy درگاه عمومی دارد. PostgreSQL و API در شبکه‌های Docker قرار دارند. Caddy با نام دامنهٔ معتبر، گواهی را خودکار مدیریت می‌کند: [مستند رسمی HTTPS](https://caddyserver.com/docs/automatic-https).

JS و CSS از build ارائه می‌شوند، ولی گزارش‌های `/research/` و `/strategies/` با کنترل نشست و نقش مدیر از `PUBLIC_ARTIFACTS_DIR` خوانده می‌شوند. نام تاریخی این متغیر به معنی دسترسی عمومی HTTP نیست. این پوشه در volume مستقل `public_artifacts` ماندگار است؛ خروجی تازهٔ پردازش بدون rebuild در دسترس قرار می‌گیرد و در پشتیبان فایل‌ها هم حفظ می‌شود.

Compose منتظر سلامت وابستگی می‌ماند: [ترتیب راه‌اندازی در مستند Docker](https://docs.docker.com/compose/how-tos/startup-order/). شبکهٔ `172.30.47.0/28` برای تشخیص دقیق IP پروکسی استفاده شده است. اگر این بازه با شبکهٔ سرور هم‌پوشانی دارد، هر سه IP، subnet و `TRUSTED_PROXIES` را هماهنگ تغییر دهید.

ساختار دیتابیس فقط هنگام ایجاد volume خالی، به ترتیب SQLهای canonical ساخته می‌شود. کاربر اجرای برنامه superuser نیست. فایل‌های SQL اولیه را روی دیتابیس پرشده دوباره اجرا نکنید. تغییر رمزهای PostgreSQL در env، رمزِ نقش موجود در volume را خودکار تغییر نمی‌دهد.

## ۳. ساخت مدیر

پس از سالم شدن app:

```bash
python3 deploy/create_admin.py --username owner --email owner@example.com
```

رمز جدید باید دست‌کم ۱۵ نویسه، حداکثر ۷۲ بایت و غیررایج باشد؛ با Argon2id ذخیره می‌شود. رمز در ورودی مخفی پرسیده و از stdin به برنامه داده می‌شود. این فرمان حساب موجود را تغییر نمی‌دهد. ثبت‌نام عادی همیشه حساب بدون نقش مدیر می‌سازد.

## ۴. انتقال دادهٔ بازار بدون حساب‌های شخصی

دیتابیس تازه هیچ شرکت یا امتیاز واقعی ندارد. سلامت نصب به معنی وجود داده یا تازه بودن امتیازها نیست. برای انتقال از دستگاه فعلی، با Python محیط پروژه و `pg_dump` هم‌نسخه یا جدیدتر از PostgreSQL منبع:

```powershell
.venv/Scripts/python.exe deploy/export_market_data.py --env-file go-app/.env --output .runtime/market.dump
```

فقط schemaهای `core`، `ingestion`، `raw`، `fundamentals`، `market` و `analytics` صادر می‌شوند. نگاشت‌های شرکت/نماد/گزارش در فایل جداگانهٔ `.runtime/market.identity.csv` قرار می‌گیرند؛ نگاشت‌های کاربر و سبد و یادداشت‌های آزاد کنار گذاشته می‌شوند. حساب‌ها، دارایی خانواده، اطلاعات کارگزاری، گفتگو و سبد خصوصی صادر نمی‌شوند. هر دو فایل را از مسیر امن به سرور منتقل کنید؛ در Git قرار ندهید.

روی دیتابیس **تازه و خالی** مقصد، پیش از باز کردن دسترسی کاربران:

```bash
docker compose --env-file deploy/.env stop app web
docker compose --env-file deploy/.env cp market.dump db:/tmp/market.dump
docker compose --env-file deploy/.env exec -T db pg_restore -U rfa_owner -d company_financial --data-only --disable-triggers --single-transaction --exit-on-error --no-owner --no-acl /tmp/market.dump
docker compose --env-file deploy/.env cp market.identity.csv db:/tmp/market.identity.csv
docker compose --env-file deploy/.env exec -T db psql -U rfa_owner -d company_financial -v ON_ERROR_STOP=1 -c "\copy core.legacy_entity_map(id,source_system,source_table,legacy_key,entity_type,target_uuid,mapping_method,confidence,created_at) FROM '/tmp/market.identity.csv' WITH (FORMAT CSV, HEADER true)"
docker compose --env-file deploy/.env up -d --wait
```

این دستورها برای merge با دیتابیس دارای داده طراحی نشده‌اند. در صورت شکست واردکردن، خطا را بررسی کنید؛ بدون بررسی دوباره روی مقصد نیمه‌واردشده اجرا نکنید. ساخت مدیر پیش یا پس از انتقال ممکن است، زیرا schema حساب‌ها وارد نمی‌شود.

## ۵. ورودی‌های پژوهش و به‌روزرسانی تحلیل

نسخهٔ قفل‌شدهٔ مدل با بستهٔ مرحلهٔ ۲ و خروجی‌های عمومی موجود همراه منبع آماده می‌شود. پردازش تازهٔ FactorMix، ReportFlow و P1/P3 علاوه بر کد، به بستهٔ کامل بازار، بایگانی مالی، قرارداد قفل‌شده و snapshotهای پژوهش نیاز دارد. این‌ها از پوشه‌های محلی و حساب‌های شخصی به‌طور خودکار کپی نمی‌شوند. انتقال صرف PostgreSQL جایگزین این بسته‌ها نیست.

قبل از فعال کردن گردش روزانه، بسته‌های دارای manifest را به مسیرهای متناظر در volume خروجی پژوهش منتقل و hashهای آن‌ها را تأیید کنید. ورودی‌های `V1237_*` در [راهنمای راه‌اندازی جدا](../docs/ISOLATED_SETUP.fa.md) مستندند. نرسیدن ورودی باید به خطای مشخص یا نبود داده منجر شود؛ داده یا رتبهٔ ساختگی تولید نمی‌شود.

در این انتشار، پردازش کاغذی خودکار و دارایی خانواده به‌طور پیش‌فرض غیرفعال‌اند. برنامهٔ مرورگر برای مقایسه‌های عمومی از خروجی‌های ثبت‌شده استفاده می‌کند؛ این خروجی‌ها با تاریخ خودشان نمایش داده می‌شوند. صفحهٔ صورت‌های مالی مسیر PostgreSQL دارد؛ دادهٔ بدون واحد مشخص نمایش داده نمی‌شود و بدون شواهد تعداد سهام، مبلغ به «هر سهم» تبدیل نمی‌شود.

پس از واردکردن داده، با حساب مدیر وضعیت تازگی را بررسی و از دکمهٔ موجود به‌روزرسانی امتیازها استفاده کنید. دریافت داده، بازمحاسبهٔ امتیاز، رتبه‌بندی و حسابداری کاغذی عملیات جداگانه‌اند؛ وضعیت هرکدام باید بررسی شود.

## ۶. سلامت و گزارش‌ها

- `/api/health/live`: زنده بودن فرایند؛ عمومی.
- `/api/health/ready`: اتصال PostgreSQL و وجود ساختار لازم؛ عمومی؛ نبود دیتابیس/ساختار پاسخ ۵۰۳ می‌دهد.
- `/api/health/shadow`: اتصال، مدل و تازگی داده؛ نیازمند ورود.
- `/api/me`: وضعیت حساب و نقش فعلی؛ نیازمند ورود.

```bash
docker compose --env-file deploy/.env logs --tail 100 app web
```

درخواست‌های ورود، ارسال کد، API و چت محدودند. در production فقط نشست تصادفی با کوکی `__Host-rfa_session` پذیرفته می‌شود؛ JWT قدیمی پذیرفته نمی‌شود. کوکی Secure، HttpOnly و SameSite=Strict است؛ عمر مطلق ۱۲ ساعت و بی‌کاری مجاز ۳۰ دقیقه است. خروج، نشست را از دیتابیس حذف می‌کند. نقش و فعال بودن حساب در هر درخواست از دیتابیس خوانده می‌شود. درخواست نوشتن با کوکی به Origin مجاز و بدنهٔ غیرخالی به Content-Type برابر application/json نیاز دارد. فرانت و API را روی یک مبدأ HTTPS نگه دارید.

## ۷. پشتیبان‌گیری و ارتقا

```bash
python3 deploy/backup.py
```

dump کامل و runtimeهای برنامه در پوشهٔ `backups` ایجاد می‌شوند. این پشتیبان حاوی اطلاعات خصوصی است؛ یک نسخهٔ حفاظت‌شده بیرون سرور نگه دارید. در زمان پشتیبان‌گیری، پردازش‌های نوشتن پژوهش را متوقف کنید؛ snapshot دیتابیس و فایل‌های runtime یک تراکنش مشترک نیستند. فایل `deploy/.env` و کلید رمزگذاری را جدا و امن نگه دارید؛ بدون آن بازیابی رمزهای رمزگذاری‌شده ممکن نیست.

بازیابی را ابتدا روی یک مقصد جدا آزمایش کنید. پس از بازیابی کامل، نشست‌های بازیابی‌شده را با حذف محتویات `auth.sessions` باطل کنید تا نشست لغوشدهٔ قدیمی دوباره معتبر نشود. dump کامل شامل ساختار است و نباید روی ساختار پرشدهٔ فعلی بدون برنامهٔ مشخص بازیابی اجرا شود. تغییر schema در ارتقا باید با migration بررسی‌شده و پشتیبان انجام شود.

برای ارتقای دیتابیس موجود، ابتدا migrationهای شمارهٔ ۱۴۰ و ۱۵۰ را مطابق [راهنمای امنیت](SECURITY.fa.md) اعمال کنید؛ اجرای دوبارهٔ SQLهای اولیه لازم نیست. برای ارتقای کد بدون حذف داده:

```bash
python3 deploy/backup.py
docker compose --env-file deploy/.env up -d --build --wait
```

از `down --volumes` روی سرور واقعی استفاده نکنید؛ volumeها دادهٔ ماندگار برنامه‌اند. محدودکننده‌های درخواست و کدهای تأیید در حافظهٔ یک فرایندند؛ این بسته برای **یک replica** است. restart کدهای تأیید در انتظار را باطل می‌کند. چند replica به مخزن مشترک کد و rate limit نیاز دارد.

## وضعیت اعتبارسنجی این تغییر

آزمون‌های انجام‌شده و مواردی که هنوز به سرور واقعی وابسته‌اند در [VERIFICATION.fa.md](VERIFICATION.fa.md) ثبت می‌شوند. ساخته‌شدن فایل‌های Docker معادل اجرای موفق کانتینر، صدور گواهی واقعی، تحویل ایمیل واقعی یا اعتبارسنجی دادهٔ روز نیست.

در اجرای مستقیم Go، آدرس پیش‌فرض فقط `127.0.0.1` است. Compose متغیر HOST را صریح تنظیم می‌کند. API مدیریتی Caddy غیرفعال است؛ تغییر تنظیمات آن با restart سرویس web اعمال می‌شود.
